## Readings of the rule I had to make

- R1, what a doubt is. The section 3 opening ("A doubt recorded by a suite's curators, an originating paper or
  either auditor fails the entry") is read as a doubt bearing on a kept criterion (1 to 6) or on the section 4
  check, counted under that criterion. Doubts on matters section 3 drops (time order, grouped rows, leaks,
  duplicates, designed sampling, "too easy", "outdated", "not representative") do not fail. Why: the flow table
  counts every failure under a criterion, and applying the opening to dropped matters would bring them back.
  Alternative: every recorded doubt fails; then APSFailure and skin-segmentation also fail (both carry curators'
  split or leak doubts) and all seven fail.
- R2, factor expansion (criterion 6). As bart() expands a data frame: a two-level factor is one column, a
  k-level factor k columns (dbarts makeModelMatrixFromDataFrame). Matters only for Internet-Advertisements: 1,558
  columns this way, 3,113 under full one-hot coding, which would fail criterion 6.
- R3, listed minority share (criterion 4). The suite's MinorityClassPercentage for a suite file, else the donor's
  documented class distribution. Where no source lists one, criterion 4 is not established (not a PASS).
- R4, a suite's edit to values (not rows). Criterion 1 allows a suite's row edits "since they choose no target
  and no predictor"; I read that reason as covering an unrecorded value edit (missing values filled), which is
  then recorded in the screen file, not failed. Section 4 fails only an unexplained row or column count. Applies
  to Internet-Advertisements (and nomao, which fails earlier). Alternative: an unrecorded value edit is an
  auditor's doubt that the file is the described data, failing at section 4.
- R5, types. "With its predictors as the source lists them" covers the types the donor lists (numeric or
  nominal), since a type changes how a predictor enters the fit. Decides cylinder-bands, together with the
  curators' recorded doubt.
